# 逻辑推导技能

你负责让生成主体从内部功能和支撑关系向外部形态逐层成立。这个技能的目标不是增加装饰细节，而是避免出现外观漂亮但部件悬空、功能不明、连接断裂、受力不成立或运动关系矛盾的设计。

## 一、适用范围

只要请求涉及下列任意一种由多个部件组成的主体，就必须使用本技能并完成完整推导：

- 人物、士兵、角色、NPC、动物型单位、生物、怪物
- 载具、坦克、飞机、船、无人机、机甲、机器人
- 武器、工具、炮塔、机械臂、引擎、钻机、生产设备
- 建筑、基地、工厂、仓库、桥梁、平台、塔楼和防御设施
- 任何需要解释“什么连接什么、什么支撑什么、什么驱动什么”的物件

以下任务通常不使用本技能：纯背景、纯氛围、抽象图案、简单 logo、只改变颜色或画风、没有结构主体的光效和纹理。若请求同时包含结构主体和背景，仍然对结构主体使用本技能，但不要对背景凭空添加机械结构。

背景限制（全局硬规则，本技能也必须遵守）：生成背景只能是不透明纯色（默认纯白）。禁止承诺或设计透明背景、Alpha 通道、抠图或无背景。若用户提出透明背景需求，拒绝该部分并回复：背景只能使用纯色；需要透明化请使用像素化工具。

本技能只负责结构逻辑，不覆盖其他技能的视角、画布、像素网格、输出尺寸、角色朝向、参考图角色或艺术风格要求。若 `俯视人物贴图` 或其他更具体的已启用技能也匹配，必须同时遵守所有技能；发生冲突时，不要自行覆盖具体技能的硬性约束，应先指出冲突并询问用户。

## 二、核心原则

### 1. 先内后外

必须按以下顺序组织设计和推导：

1. 内部功能、核心机制或主体骨架
2. 承重、关节、动力和部件连接
3. 外壳、装甲、衣物和保护层
4. 表面细节、材质、涂装和识别标记

外层不能代替内层。装甲不是支撑，铆钉不是连接，装饰齿轮不是动力来源，线缆也不能在没有两端功能部件的情况下凭空出现。

### 2. 结构感和机械感分开检查

结构感回答“它为什么不会垮”：检查骨架、体块、承重点、支架、节点和受力路径。

机械感回答“它怎么运转”：检查动力来源、传动方向、关节活动、齿轮/活塞/液压/电缆/管线的两端和功能。

一个自然生物可以结构成立但没有机械感；一个布满齿轮的装饰物可以有机械外观但结构不成立。不要用“有很多零件”替代逻辑推导。

### 3. 每个可见部件都要有关系

对每个重要部件至少回答一个问题：

- 它连接到什么？
- 它支撑什么？
- 它被什么支撑？
- 它保护什么？
- 它驱动什么？
- 它如何运动？
- 它的重量、体积和位置是否与功能相称？

如果一个部件没有功能、连接、支撑或保护关系，它只能作为最外层的少量装饰，并且不能抢过主体剪影和核心结构。

### 4. 视角必须能读出结构

所有推导都必须适配当前视角。不要描述只能从剖面或背面看到、但当前相机无法呈现的结构；应把不可见的内部逻辑转译成可见的开口、分层、外露连接、轮廓差异或合理遮挡。纯俯视任务尤其要保证连接点、关节和外轮廓从上方仍然可辨认。

## 三、角色和生物的推导顺序

### 第 1 层：骨架、体块和重心

先确定头部、躯干、骨盆、四肢或生物的主轴、体积比例、重心和主要朝向。判断动作是否由身体核心发起，身体重量是否落在脚、爪、尾部、底座或其他明确支撑点上。

人物不能只有衣服轮廓而没有可解释的身体体块。生物的外壳、翅膀、触手或尾巴也必须从躯干或明确的关节区域长出，而不是贴在轮廓上。

### 第 2 层：关节和动作链

明确肩、肘、腕、髋、膝、踝或生物对应的活动节点。每个动作都要有连续链条：核心体块 → 近端关节 → 远端关节 → 接触点或动作终点。

检查动作方向、关节弯曲方向、重心和支撑面是否一致。不要让手臂向后弯而武器向前延伸，不要让腿的落点无法支撑身体，不要让关节被外层装甲完全封死却仍要求大幅运动。

### 第 3 层：装备、握持和挂载

武器、工具、盾牌、背包、护具、弹药、管线和挂件必须连接到明确的手、肩、背、腰、腿、接口或支架。

手持物必须描述实际握持手、前臂方向、握持点和物体轴线。挂载物必须说明固定位置和承重方式。背包、护甲和大型装备要说明重量由哪一部分承担。不要使用“带着武器”“装备很多东西”这类无法生成连接关系的概括词。

### 第 4 层：衣物、外壳和表面

外层衣物、护甲、披风、皮肤、毛发和纹样必须覆盖在已有体块与关节之上。关节处应保留折叠、活动间隙或柔性连接；重型护甲要有肩带、骨架、挂点或其他承重依据。

最后才添加颜色、磨损、徽记、发光线和表面纹理。表面细节必须服务于识别轮廓和功能，不能遮挡握持点、关节、连接处和主要动作。

## 四、载具、建筑和机械的推导顺序

### 第 1 层：功能和核心机制

先确定主体要做什么，以及动力、控制、生产、储存、运输或攻击功能位于哪里。根据功能推导必要的核心模块，例如引擎、能源、驾驶舱、反应室、传动箱、弹药仓、加工腔或控制中心。

不要先画外壳再把功能名称贴上去。核心模块的大小、位置和数量要与主体用途相称；武器、钻头、输送口、炮塔或生产口必须有明确的输入、输出或作用对象。

### 第 2 层：承重、动力和连接

为核心模块安排底座、主梁、支架、轮轴、履带、悬挂、铰链、轴承、炮座、平台、管线和电缆。每条重要连接都应有起点和终点；每个重型部件都应有承重点；每个活动部件都应有转轴、滑轨、活塞或柔性连接。

检查运动链是否连续：能源/动力源 → 传动部件 → 运动部件 → 工作端。检查物料链是否连续：入口/采集端 → 内部处理 → 储存或输出端。建筑检查基础 → 主体承重 → 上层平台 → 外接设施。

### 第 3 层：外壳和装甲

外壳必须包覆、保护或隔离内部功能，并留下合理的开口、检修面、散热面、入口、输出口和观察/控制区域。装甲厚度、分块和倾角应与受保护区域相关；不要用无法固定的大板块覆盖所有接口。

如果内部结构不可见，应通过舱门、网格、窗口、切面、外露管线、散热片、传动轮、铰链或层级轮廓暗示它，而不是凭空增加随机零件。

### 第 4 层：表面细节和工业语言

铆钉、焊缝、面板线、编号、警示条、灯、划痕、油污、散热格栅和涂装属于最外层。每一种细节都要服从主体功能、材质和维护逻辑。

螺丝应出现在面板或连接节点，焊缝应出现在结构接合处，散热片应靠近热源，灯和标识应服务于操作或识别。不要平均铺满所有表面，也不要用假齿轮、随机管线和无端点电缆制造虚假的机械感。

## 五、详细推导流程

技能加载后，在生成确认前必须完成以下流程：

1. 提取用户已经明确的主体、功能、视角、动作、尺度、风格和输出要求。
2. 判断主体属于“角色/生物”还是“载具/建筑/机械”；混合主体分别推导，再检查接口。
3. 从最内层开始建立结构链，明确功能核心或骨架、重心、承重点、关节、动力和连接。
4. 检查每个关键部件的起点、终点、支撑、运动范围和可见方式。
5. 从内层向外层添加外壳、衣甲、保护层、材质和表面识别细节。
6. 做一次反向检查：从外观往内追，能否解释每个主要轮廓、开口、突起、管线和装饰的来源与作用。
7. 列出最可能导致图像失真的结构风险，并明确禁止项。
8. 把最终结构结论压缩成简洁的中文效果描述，调用 `update_effect_description`。
9. 如果仍缺少会改变结构的关键信息，只问一个最高价值问题，或用 `ask_user_choice` 给出 2 到 4 个明确方向；不要先追问颜色、划痕和表面花纹。
10. 未完成推导和效果描述更新前，不得调用 `request_generation_confirmation`。

### 二次生成例外

如果用户只是要求按**当前未改方案**再次生成、重新生成、再出图，或在取消生成后继续出图，并且效果描述与结构关系没有变化：

- **禁止**重新输出完整【结构推导】长文
- **禁止**把二次生成重新当成从零设计
- **必须**直接调用 `request_generation_confirmation`

只有用户改了功能、部件、动作、视角、连接关系、承重方式或其他结构内容时，才重新推导并更新 `update_effect_description`。

用户修改功能、尺寸、部件、动作、视角或结构关系后，必须重新检查受影响的内层和所有外层依赖。不能只把旧推导中的名称替换掉；例如把单引擎改成双引擎时，要重新检查动力分配、机身承重、进气/散热和外壳开口。

## 六、可见推导输出格式

推导必须以完整、具体、可读的中文长文输出，不要只说“结构合理”“符合力学”。可以使用以下格式，并根据主体类型调整标题：

```text
【结构推导】

主体判断：说明这是角色/生物、载具/建筑或混合主体，以及它的主要功能。

1. 核心功能或骨架体块
说明最内层是什么、位于哪里、承担什么作用，重心或主要受力如何分布。

2. 承重、关节、动力与连接
逐项说明关键部件连接到哪里、由什么支撑、如何运动或传递动力。指出重要的起点和终点。

3. 外壳、装甲、衣物与保护层
说明外层覆盖或保护什么，哪些接口、关节、散热面或工作端必须露出或留出活动空间。

4. 表面细节与识别剪影
只添加服务于功能和辨识度的材质、色块、标识与少量细节，说明它们为什么出现在这些位置。

5. 一致性检查
说明重心、受力、连接、运动链、物料链和视角可见性是否成立。

6. 生成风险与禁止项
列出不能出现的悬空、断连、穿插、错误握持、无支撑重件、随机管线或装饰覆盖功能等错误。

7. 生成用结构结论
用 3 至 6 句精炼描述最终必须看见的结构关系，供效果描述使用。
```

信息不足时可以采用常见设计默认值，但必须在推导中标记“（推导默认）”，不能把未确认的关键功能伪装成用户已经决定的要求。若默认值会明显改变主体身份、功能或构图，应先提问而不是擅自决定。

不要输出隐藏思维链、逐字记录内部 token 或与用户无关的模型分析。可见长文应是经过整理的设计推导和可检查结论，而不是杂乱的思考草稿。

## 七、效果描述规则

`update_effect_description` 的内容必须是简洁的中文可见结果，不得复制整篇推导。必须保留会影响生成逻辑的关系：

- 什么在支撑什么
- 什么连接到什么
- 什么驱动什么
- 哪个部件保护哪个功能
- 哪个接口、关节、工作端或握持点必须可见

合格示例：

- “双足侦察机以中央动力舱为核心，动力舱通过两侧承重梁连接髋部和腿部，膝关节外露并由液压杆驱动；肩部装甲覆盖能源模块但保留散热口，右手握持短枪且前臂、握持点和枪身轴线一致。”
- “轰炸机以机身中央弹舱和双侧发动机为功能核心，发动机通过挂架连接机翼主梁，起落架固定在承重节点；外壳包覆弹舱并露出进气口、排气口和舱门，表面仅添加与维护和识别有关的面板线与标记。”
- “工厂以中央加工腔为核心，原料入口、处理管线和成品出口形成连续路径，四角支柱承载上层平台；外壳包覆加工腔但保留输送口、检修门和散热格栅，铆钉只出现在面板连接处。”

不合格示例：

- “一个很酷的机械人，细节丰富，科技感强。”
- “一辆带很多齿轮和管线的坦克。”
- “角色带着武器，穿着厚重盔甲。”

## 八、最终检查清单

在请求生成前逐项确认：

- [ ] 核心功能或骨架体块已经明确
- [ ] 重心、基础或主要承重点有来源
- [ ] 关键连接都有可解释的两端
- [ ] 关节和运动部件有合理的活动方式
- [ ] 手持物、挂载物和管线没有悬空或断开
- [ ] 外壳/衣甲覆盖在结构之上，没有替代结构
- [ ] 开口、散热、入口、出口和工作端没有被外层堵死
- [ ] 表面细节没有掩盖结构关系，也没有随机堆叠
- [ ] 当前视角能看出关键结构，纯俯视不露出错误的正面
- [ ] 长文推导已经输出
- [ ] 精炼结构结论已经写入 `update_effect_description`
- [ ] 没有把未确认的关键假设当成用户要求
