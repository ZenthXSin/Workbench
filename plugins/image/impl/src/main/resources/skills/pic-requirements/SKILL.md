# 需求访谈技能

当创作需求模糊、存在多种合理解读、关键参数未定、参考图用途不明，或用户描述与已有效果描述冲突时，你负责通过多轮访谈把需求逐层澄清到可以直接生成的程度，并把每一轮确认的设计决策沉淀到工作区记忆。这个技能的目标不是无意义闲聊，而是用最少的问题消除所有会实质改变可见结果的不确定分支。

## 一、适用范围

只要满足下列任意一条，就必须加载并使用本技能，且访谈收敛前不得进入生成流程：

- 需求存在模糊表述：例如"做个帅气的角色""随便设计一个武器""看着办"。
- 需求有多种合理解读，且不同解读会实质改变可见结果：例如主体类型、风格、构图或用途未定。
- 关键参数未定：主体、风格、构图、光源、色彩、尺寸/数量、背景等会写进效果描述的要素缺失。
- 参考图用途不明：已附加参考图，但用户没有说明是借鉴风格、保留主体做变体、还是按图修改。
- 用户描述与已有效果描述冲突：新说法与已收敛的效果描述矛盾，需要先确认以哪个为准。

以下情形不适用本技能，不要无谓访谈：用户需求已完全明确、无歧义，可以直接构造效果描述；或用户只是要求按当前已收敛方案再次生成（重出图、重新生成），此时直接走生成确认。

## 二、强制前置

- 访谈未收敛前，禁止构造图像提示词、禁止调用 `update_effect_description`、禁止请求生成确认。
- 访谈期间不要假设"有一个合理默认值就可以开始"；所有会实质改变可见结果的分支都必须收敛。
- 如果某个事实自己就能查到（已附参考图的元数据、会话历史、工作区记忆、已有效果描述），不要把它作为问题问用户。

## 三、访谈机制

访谈改编自设计树方法，把需求拆成决策树逐层收敛：

1. **拆决策树**：从最根本的决策出发（主体是什么），每个决策分出依赖它的子决策（主体定了之后才有构图、动作；构图定了之后才有光源、色彩）。先问能独立回答的根决策，再问依赖它的子决策。
2. **按轮提问**：每轮只问当前"前沿"问题——即所有前置决策已经确定、现在可以回答的问题。把本轮问题编号列出，并为每个问题给出推荐答案，格式如下：
   - ❓ Q1 - 标题: 问题体，包含 2 到 4 个互斥选项；
   - ➡️ 推荐答案: 从选项中选一个默认推荐。
3. **一轮一问**：由于应用强制所有面向用户的提问走 `ask_user_choice`，每个问题必须单独用一次 `ask_user_choice` 提出，把 ❓ 编号和 ➡️ 推荐答案写进该次提问的正文与选项中；不要在本轮所有回答返回前提前问下一轮问题。
4. **答案重塑决策树**：用户每轮的回答会改变后续可问的问题集合，重新计算前沿后再进入下一轮。已确认的决策不得在同一任务中重复提问。
5. **能查的不问**：参考图角色、会话里已出现过的信息、工作区记忆中的既有偏好，直接使用，不进入问题列表。
6. **前沿为空即结束**：所有分支收敛、没有待定决策时，访谈结束，进入文档沉淀与生成衔接。

示例问题格式：

```text
❓ Q1 - 主体类型: 这个单位是什么？(a) 步兵 (b) 载具 (c) 建筑 (d) 生物
➡️ 推荐答案: (a) 步兵
```

## 四、收敛标准

访谈结束、可以进入生成流程，必须满足下列全部条件之一：

- 主体、风格、构图、光源、色彩、尺寸/数量、参考图用途、明确禁止项全部确定；或
- 用户明确表示"就这样开始""可以生成了"等收敛信号。

收敛后不要继续追问低价值细节；没有在收敛标准之外的补充问题空间。

## 五、文档沉淀

- 仅当用户明确要求记住某项内容，或访谈收敛后确立了可复用的跨会话稳定偏好（常用风格、默认尺寸、常见主体，且用户表达为长期偏好）时，调用 `add_workspace_memory` 写入工作区记忆，用途说明必须明确，例如"记录用户明确要求记住的风格偏好：xx"。
- 访谈过程中确认的单次设计决策（主体、构图、配色等本轮创作内容）不写入记忆——它们是本次创作的效果描述内容，不是跨会话偏好。
- 不写入临时性单次指令（例如"这张图左边加个盾牌"这类只影响当次生成的细节）。

## 六、与生成衔接

- 访谈收敛后，用 `update_effect_description` 把已确认的完整预期效果汇总成简洁的中文描述（主体、风格、构图、光源、色彩、尺寸/数量、参考图用途、明确禁止项），再走 `request_generation_confirmation`。
- 若用户随后只要求按同一方案重出图，不要重新访谈，直接进入生成确认。
- 若后续请求新增或改动了会实质改变可见结果的需求，先确认新决策，再更新效果描述；只改动单次生成细节的，不必重新访谈。
