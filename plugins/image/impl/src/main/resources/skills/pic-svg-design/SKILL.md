# SVG 设计规范技能

凡用户要求矢量图、SVG、可无限缩放图形、图标、Logo、插画风图形，且将用 generate_svg 生成时，必须先按本技能组织设计，再调用工具生成。

## 一、适用范围

只要满足下列任意一条，就必须加载并使用本技能：

- 用户明确要求"SVG""矢量图""矢量图形""可无限缩放图形"。
- 用户要求图标、Logo、标识、徽章、按钮图标、插画风图形等适合矢量表达的内容。
- 生成结果将由 generate_svg 工具以 SVG 形式产出。

## 二、硬性限制（运行时强制）

生成结果会被运行时 sanitizer 校验并交给指定渲染器绘制，以下限制必须无条件遵守，违反会导致元素被移除或渲染失败：

- **根元素**：必须是最外层 `<svg>`，且必须带 `viewBox="0 0 W H"`（例如 `viewBox="0 0 1024 1024"`）；缺 viewBox 时宽高会被自动补全，可能造成布局偏差。
- **禁止元素**：`script`、`foreignObject`、`image`、`audio`、`video`、`iframe`、`animation` 一律不得出现。
- **禁止属性**：所有 `on*` 事件属性（onclick 等）一律不得出现。
- **禁止外部引用**：`href` / `xlink:href` 只能以 `#` 开头引用文档内部的 id（如 `#grad`），不得引用任何外部 URL（外部图片、字体、样式表、脚本均不可）。
- **禁止 url()**：style 属性中不得包含 `url()` 引用；不得使用外部 CSS。
- **字体**：文本渲染依赖设备默认字体，不得假设特定字体族可用；画面文字尽量少用，确需文字时用 `<text>`，并用 `text-anchor` 显式控制对齐方式。
- **边界**：所有内容必须完整落在 viewBox 之内，不得溢出画布。

渲染器支持的能力范围：基础形状（rect、circle、ellipse、line、polygon、polyline、path）、渐变（linearGradient、radialGradient）、pattern、text、transform、clipPath / mask 以及基础 filter。设计时只使用这些能力，不依赖任何被禁止的特性。

## 三、坐标与结构原则

- 统一使用 viewBox 坐标系，不要混用像素与相对单位；以 `<g transform="translate(...) scale(...)">` 分组管理整体布局。
- 先整体布局（大形），再逐层细化细节；不要一开始就陷进局部。
- 用 `<defs>` 集中定义复用的渐变、符号与 pattern，通过 id 以 `#` 引用，避免重复定义。
- 图层顺序即绘制顺序：背景 → 大形 → 中层 → 前景 → 高光，按这个顺序排列元素。
- 保持结构清晰：用 `<g>` 做语义化分组并配合注释式命名习惯，方便用户要求修改时快速定位与局部替换。

## 四、视觉质量原则

- 明确光源方向，用渐变与明暗表达体积；linearGradient 通过 gradientTransform 控制渐变角度，让光感方向一致。
- 配色克制：主色加点缀色，饱和度与明度有意识控制，避免全图高饱和刺眼。
- 形状语言统一：圆角半径、描边粗细、线帽风格在整张图中保持一致。
- 留白与呼吸空间；元素之间借助数学坐标精确对齐，避免随手摆放。
- 避免无意义装饰，每个元素都必须服务造型目的。

## 五、修改衔接

- 用户要求修改时，保留已确认的结构与风格，只改动指定部分，不要顺手重画其他区域。
- 对可能反复调整的区域（配色、文字、局部图形），预先用 `<g>` 隔离成独立分组，便于精准修改。

## 六、与工具衔接

- 收敛需求后直接调用 generate_svg 生成，把设计要点（画布尺寸、构图、配色、光源方向、核心造型）写进 instruction；不要先输出大段 SVG 代码让用户等待。
- 关键参数含糊时（用途、风格、配色、尺寸比例未定），先按应用规则走需求访谈收敛，再生成。
